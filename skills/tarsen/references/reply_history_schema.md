# Reply History Store - Schema & Setup

## Decision: Google Sheet (recommended)

Rich already runs Google Sheet-based logging for receipts and Bishop AI finances, and the n8n Google Sheets node is rock solid. Start with a Sheet. If volume crosses ~5,000 rows or query latency starts hurting, migrate to Postgres or SQLite later. The schema below ports cleanly.

**Sheet name:** `TARSEN - Reply History`
**Tab name:** `replies`

## Columns

| Col | Field | Type | Notes |
|---|---|---|---|
| A | `id` | string | UUID generated by n8n at insert time |
| B | `timestamp_et` | datetime | ISO 8601 in America/New_York. Set at the moment the reply is posted (not drafted). |
| C | `target_handle` | string | The account being replied to, no `@` prefix |
| D | `tweet_url` | string | Full URL to the original tweet |
| E | `tweet_text` | string | Original tweet text, truncated to 500 chars |
| F | `thread_context` | string | Up to 3 prior tweets concatenated, or "none" |
| G | `tweet_type` | enum | `opinion` / `question` / `industry_take` / `insight` |
| H | `reply_style` | enum | `specific_insight` / `data_point` / `follow_up_question` / `contrarian` |
| I | `reply_text` | string | The reply that was posted |
| J | `reply_word_count` | int | Computed at insert |
| K | `approval_status` | enum | `auto` / `manual_approved` / `manual_rejected` / `pending` |
| L | `approved_by` | string | "rich" during week 1, "auto" after |
| M | `posted_at` | datetime | Same as timestamp_et if posted, blank if rejected |
| N | `likes_received` | int | Updated by daily polling job |
| O | `replies_received` | int | Updated by daily polling job |
| P | `profile_clicks` | int | If trackable; blank otherwise |
| Q | `notes` | string | Free text - flags, anomalies, "went viral", etc. |

## Indexes / lookups TARSEN needs to do

Before drafting any new reply, the workflow must answer:

1. **"Have I replied to this account today?"**
   Filter `target_handle == X` AND `DATE(timestamp_et) == today_et`. Block if count >= 2.

2. **"How many replies have I posted today total?"**
   Filter `DATE(timestamp_et) == today_et` AND `approval_status IN ('auto', 'manual_approved')`. Block if count >= today's warm-up cap.

3. **"What's working?"** (for the daily digest)
   Sort by `likes_received + replies_received * 3 + profile_clicks * 5` desc, top 5 from last 24h.

## Daily polling job

A separate n8n workflow runs at 3 AM ET:
- For every row from the last 7 days where `posted_at` is set, hit X API for current likes/replies counts
- Update columns N and O
- This is what powers the digest and the "what's working" analysis

## Migration trigger

Move off Sheets to Postgres/SQLite when:
- Row count > 5,000, OR
- Daily lookup latency > 3 seconds, OR
- Concurrent writes start causing dropped log entries

The column names above map 1:1 to a relational schema, so the migration is mechanical.
