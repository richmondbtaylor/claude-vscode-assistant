THE MEMORY SYSTEM

Foundation

Memory is how Claude remembers who you are across sessions. Without it, every conversation starts from zero.

Step 1 — Create the memory folder

~/.claude/memory/

Step 2 — Create MEMORY.md

This file is always loaded into context at startup. Keep it under 200 lines. It's a pointer index, not the actual content.

~/.claude/memory/MEMORY.md
## Memory Index

- [user_profile.md](memory/user_profile.md)              Who I am, my business, my goals
- [feedback_no_em_dashes.md](memory/feedback_no_em_dashes.md)  Never use em dashes
- [feedback_always_pdf.md](memory/feedback_always_pdf.md)     Output PDFs, not HTML
- [feedback_human_first.md](memory/feedback_human_first.md)   AI amplifies, never replaces
- [brand_guidelines.md](memory/brand_guidelines.md)           Colors, fonts, voice

Step 3 — Write individual memory files

~/.claude/memory/feedback_no_em_dashes.md
---
name: No Em Dashes
description: Never use em dashes in any output
type: feedback
---

Never use em dashes (—) in any response or document.
Use a hyphen (-) or restructure the sentence instead.

The four memory types

User

Who you are

Your name, role, expertise, business context. This is the baseline — write it first.

Feedback

Corrections & preferences

Every time you correct Claude twice on the same thing, save it. This is the highest-ROI memory type.

Project

Active work context

Current goals, active initiatives, deadlines. Update when projects change.

Reference

External pointers

Google Sheets IDs, Drive folder paths, Slack channels, API endpoints.

High-ROI memories to write first 1. Your name, business, what you do. 2. Communication style (no emojis, no em dashes, terse responses). 3. Output format rules (PDF vs HTML, auto-upload). 4. Brand voice and banned phrases. 5. Any rule you've had to correct Claude on more than once.

BUILDING SKILLS

Core System

Skills are reusable prompt frameworks stored as files. Claude reads the SKILL.md when you invoke the skill by name.

Folder structure

~/.claude/skills/
└── your-skill-name/
    └── SKILL.md

The anatomy of a great SKILL.md

SKILL.md template
# Skill Name

## Overview
One paragraph: what this skill does and when to use it.

## Trigger Conditions
- "generate a weekly batch"
- "analyze viral content"
- User uploads a receipt

## Framework
Name it. Give it an acronym (CAPTAIN, PRISM, CLOUTER).
Each letter = a phase or principle.

## Step-by-Step Execution
### Phase 1: [Name]
1. Do this
2. Then this

## Output Format
File types, section names, length guidelines.

## Hard Rules
- Never do X
- Always include Y

## Examples
1-2 example inputs and expected outputs.
The trigger description is everything Write it to match how you actually talk, not formal language. If Claude doesn't invoke the skill at the right time, rewrite the trigger first. It is the most important line in the entire file.

How to build your first skill

  1. 01
    Identify a repeated task. What do you ask Claude every week that requires the same context or setup?
  2. 02
    Write the framework first. Give it an acronym. Each letter = a phase. This makes outputs consistent and teachable.
  3. 03
    Draft the SKILL.md. Focus on what triggers it, what phases to run, what the output must look like, what it must never do.
  4. 04
    Test it on a real task. Refine based on output quality. Iterate until it's tight.
  5. 05
    Use skill-creator to evaluate. The meta-skill benchmarks your skill against sample inputs and scores consistency.

SETTINGS CONFIGURATION

Permissions

Controls what Claude is allowed to do without prompting you every time.

~/.claude/settings.json
{
  "permissions": {
    "allow": [
      "Bash(python scripts/generate_pdf.py:*)",
      "Bash(python scripts/upload_gdrive.py:*)",
      "Bash(pip install *)",
      "Bash(powershell -File scripts/auto-push.ps1)"
    ],
    "additionalDirectories": [
      "C:/Users/yourname/Downloads",
      "C:/Users/yourname/Documents/Projects"
    ]
  }
}

Add to allow: any Python scripts you run repeatedly, pip install, PowerShell scripts, any CLI tool Claude needs to invoke silently.

additionalDirectories opens folders outside ~/.claude for Claude to read and write — add your Downloads folder, project directories, anywhere Claude needs access.

BUILD ORDER

Roadmap

If starting from scratch, follow this sequence.

W1

Foundation

  • Install Claude Code and authenticate
  • Create ~/.claude/memory/MEMORY.md
  • Write 5 core memory files (profile, top 3 feedback items, brand voice)
  • Configure settings.json with basic permissions
W2

First Skills

  • Build your most-used skill first (the one you'd use daily)
  • Use skill-creator to evaluate and refine it
  • Add a brand/style skill so all outputs are consistent
W3

Content Production

  • Build content generation skills (captions, scripts, repurposing)
  • Add the banned-phrases reference file
  • Connect to Google Drive via upload script
W4

Automation

  • Set up PDF generation pipeline
  • Build or adapt the research agent for your niche
  • Schedule daily automation with Task Scheduler
Month 2+ — Iteration Review which skills you actually use. Cut or merge underused ones. Benchmark with skill-creator to improve consistency. Add workspace folders for A/B testing skill variations.
08

KEY LESSONS LEARNED

Hard-Won
01

The trigger description is the most important part of a skill

If Claude doesn't invoke the skill at the right time, rewrite the trigger. Be specific. Include exact phrases you actually use — not formal language.

02

Memory compounds over time

Every time Claude gives you a wrong output, ask: should this be a memory? If you'll hit this situation again, save it. These stack up fast and the system gets measurably better each month.

03

Named frameworks make skills consistent

CAPTAIN, PRISM, TOKEN — these give Claude a structure to follow. Without a named framework, outputs vary too much across sessions.

04

Hard Rules prevent recurring mistakes

Every skill needs a Hard Rules section. "Never frame AI as replacing humans" is ours. These are the guardrails that protect your brand and prevent costly corrections later.

05

Output format clarity = better outputs

Don't say "write a LinkedIn post." Say "Under 300 words, hook in first line, 3 bullet points max, no hashtags, end with one question." Specificity wins every time.

06

Build skill-creator early

It lets you benchmark other skills against sample inputs, measure consistency, and iterate without manual testing. It is the force multiplier for everything else.

07

Keep MEMORY.md under 200 lines

It is always loaded. If it gets long, consolidate or cut. Individual memory files can be longer since they are only loaded when relevant to the task.
