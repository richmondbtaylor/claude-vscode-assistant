You should see A line ending Switched to branch ..., and a new vidforge folder.

Install it

Takes a couple of minutes. You already have uv, so nothing else to set up.

cd vidforge
uv sync

Ask it what your machine can do

This is the one that answers your question. Send me what it prints and I will tell you exactly which model to run.

uv run vidforge doctor
It prints four lines platform, accelerator, torch, suggested. The accelerator line is the one that matters: it either names a graphics card and its memory, or says none detected.

What happens next

Three roads, depending on that one line. Tap whichever sounds like you.

While you are waiting, the app already works without a graphics card. The mock model renders placeholder clips so you can see the queue, the batching and the gallery for real before committing to any download.

uv run vidforge serve

You are close

  1. Run uv run vidforge setup. It picks the right graphics driver build, installs it, and downloads a model sized to your card. This is the long one: expect several GB.
  2. Render something: uv run vidforge gen "a rain-slicked alley at night"
  3. Put it on your phone: uv run vidforge serve --tunnel, then scan the QR code it prints.

Rough guide from that memory number: 8 GB or more runs the small Wan model, 24 GB runs the good one. Under 6 GB and you are better off with the cloud option below.

Not a dead end

Video models need a real graphics card. Without one, a single clip takes hours rather than minutes. Two ways round it:

  1. Rent one by the hour. RunPod or Vast.ai, a few dollars a day. Same four steps on the rented machine, then serve --tunnel and you drive it from your phone exactly as if it were under your desk.
  2. Use a service for the model, this app for everything else. Slower to set up and it gives up the no-filter part, so probably not what you want.

Tell me which and I will write that setup out properly.

Worth knowing before you spend an evening

Getting explicit output needs one more piece

The app applies no content filter. But the standard models were never trained on explicit material, so removing a filter does not conjure it up. You get mangled anatomy, not results.

The missing piece is an add-on file, a LoRA, trained for it and stacked on top of the base model. Civitai is where people get them. Download one, send me the filename, and I will wire it into your config so it loads automatically.

Same story for realism, by the way. Five seconds at 480p is where open models are right now. Good, not indistinguishable, and you will burn a lot of attempts. That is why the app batches.

If you already run ComfyUI and have a working video setup in it, skip all of this. Export the graph with Save (API Format), point vidforge at the file, and it becomes the queue and gallery on top of what you already have. Say the word and I will set that up instead.
